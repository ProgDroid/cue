**Docker deploy gotcha (2026-06-22, fixed `5ff1fed`):** first server deploy via `docker compose` failed with "unable to connect" though the container ran. Cause: compose `env_file: .env` (`.env` copied from `.env.example`) **overrode the image's `ENV`** — `BIND_ADDR=127.0.0.1:8080` made cue bind the container's **loopback**, which Docker's published port can't reach (it targets the bridge IP). Relative `DATABASE_URL` also wrote the DB to `/app/data` instead of the `/data` volume. Fix: `docker-compose.yml` now pins `BIND_ADDR=0.0.0.0:8080` + `DATABASE_URL=sqlite:/data/cue.db` + `STATIC_DIR` + `RUST_LOG` via `environment:` (overrides `env_file:`); `Dockerfile` adds `ENV RUST_LOG=info,sqlx=warn` (logs were silent because `EnvFilter::from_default_env()` emits nothing with `RUST_LOG` unset); `.env.example` split into in-container secrets vs local-only infra. **Rule: in a container bind `0.0.0.0`; keep the localhost posture at the host-publish layer (`ports: "127.0.0.1:8080:8080"`).** Full cross-project writeup: `~/.claude/learnings/docker-compose-envfile-overrides-image-env.md`.
